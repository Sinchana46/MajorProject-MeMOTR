1. Project Overview & Goals

Objective

Fine-tune MeMOTR (Memory-augmented Multi-Object Tracking with Transformers) on the IOTD (Indian Overhead Traffic Dataset) and ablate whether synthetic data augmentation improves vehicle tracking. Two novel modules under development:

ModulePurposeStatus
C1 -- PositionMLPPerspective-aware loss: extra gradient weight for distant (small) vehiclesDesigned; not yet IOTD-trained
C2 -- ThresholdAdapterScene-adaptive tau: lower detection threshold in dark scenes to recover night vehiclesInterim trained; needs IOTD calibration

Problem Statement

IssueCauseImpactFix
P1 Fixed thresholdtau=0.5 fixed regardless of lighting. Night vehicles score 0.30-0.45.Vehicles dropped in dusk/night scenes (high FN)C2: MLP mapping brightness to dynamic tau in [0.2,0.7]
P2 Perspective-blind lossL1+GIoU treats near and far boxes identicallyDistant vehicles contribute weak gradients; poor far-lane trackingC1: per-box loss weight from predicted depth/y-position

2. Architecture

MeMOTR Components

ComponentDetails
BackboneResNet-50 (ImageNet pretrained). Frozen during all fine-tuning (lr_backbone=0.0)
Encoder6-layer Deformable Transformer encoder, multi-scale deformable attention (3 scales)
Decoder6-layer decoder with detection + propagated track queries
Query UpdaterGRU-based memory module -- carries track embeddings across frames
Detection queries300 per frame (learnable positional embeddings)
CUDA opsMeMOTR/models/ops/MultiScaleDeformableAttention.cp39-win_amd64.pyd
Checkpoint size575.5 MB (weights + optimizer + scheduler state)
Max GPU memory~9,352-9,353 MB (both training arms identical)

Training Loss Components Explained

Loss TermMeaningFrame Tag
Box L1Absolute pixel error of predicted box centre and size vs ground truth (normalised 0-1)f0, f1
Box GIoUShape + overlap quality. 0 at perfect match. Penalises non-overlapping boxes too.f0, f1
FocalVehicle vs background classification confidence. Down-weights easy examples.f0, f1
f0 (frame 0)First frame of clip = detection task (find vehicles from scratch)--
f1 (frame 1)Second frame of clip = tracking task (propagate detections from f0)--

Root Cause: uav0000117_02622_v

One UAV night sequence produced 61,674 detections vs 5,505 GT -- an 11x FP explosion. Single sequence accounts for 58,115 of 69,538 total FP increase. Cause: adapter trained on daytime UA-DETRAC, computed very low brightness for UAV night footage, output tau ~0.32, admitted nearly all 300 detection queries every frame.

Excluding uav0000117: C2 is directionally correct
FP increase only +11,423 (vs +69,538). All DETRAC-only sequences show neutral or positive direction. C2 concept validated -- needs IOTD night calibration.
