This project extends MeMOTR (Memory-augmented Transformer for Multi-Object Tracking) with two targeted contributions designed to improve vehicle detection and tracking performance in adverse lighting conditions — specifically the night-time and dusk scenarios present in the Indian On-road Traffic Dataset (IOTD).

MeMOTR uses track-query embeddings that propagate across frames, giving it strong long-term association capability. However, its fixed detection threshold (tau = 0.5) is ill-suited for scenes where genuine vehicles score 0.35–0.45 (dark/low-contrast), or where background clutter produces spurious high-scoring detections in bright overexposed conditions.

📌 Project Constraint
The MeMOTR backbone and encoder are not modified — all contributions operate as lightweight modules attached after the encoder output or as post-hoc threshold adaptation. This preserves MeMOTR's pretrained generalisation while adapting its behaviour to new domains.
PyTorch 1.x CUDA Deformable DETR TrackEval UA-DETRAC VisDrone IOTD (Pending) Windows / Anaconda

Problem Statement

Issue 1 — Fixed Detection Threshold

MeMOTR's runtime tracker admits new detections only if their classification score exceeds a fixed threshold tau = 0.5. In dark/dusk scenes (IOTD), genuine vehicles frequently score 0.35–0.45, causing them to be silently dropped as false-negatives. In bright overexposed daytime footage, the same threshold admits excessive background clutter, increasing FP.

Addressed by Contribution 2 (C2)

Issue 2 — Perspective-Blind Training Loss

MOT training typically applies a uniform matching loss across all regions of the frame. In overhead IOTD footage, vehicles at varying distances from the camera appear at very different scales. A uniform λ (loss weight) penalises small-vehicle misses equally to large-vehicle misses, leading to suboptimal calibration for multi-scale scenarios.

Addressed by Contribution 1 (C1) — Pending IOTD data

Baseline Architecture — MeMOTR

MeMOTR is an end-to-end multi-object tracking framework built on a Deformable DETR backbone. It maintains persistent track queries across frames using a memory mechanism, enabling long-term identity preservation without external re-identification modules.

Novel Contributions

C2

ThresholdAdapter — Scene-Adaptive Detection Threshold

✅ Implemented & Evaluated

Hypothesis: The detection admission threshold tau should adapt per-frame to scene conditions. In dark scenes, a lower tau recovers genuine vehicles that score below the fixed 0.5 cutoff. In bright/cluttered scenes, a higher tau suppresses FP.

SceneAnalyzer

Analytic (no learnable params). Computes a 3-D scene feature vector from each frame:

  • Brightness — mean pixel intensity [0, 1]
  • Contrast — standard deviation of intensity [0, 1]
  • Track density — active track count / max_tracks [0, 1]

ThresholdAdapter MLP

Tiny 3-layer MLP: 3 → 16 → 8 → 1, then sigmoid-and-scale:

tau = tau_min + (tau_max - tau_min) * sigmoid(MLP(scene_vec))
     = 0.3 + 0.4 * sigmoid(...)    ∈ [0.3, 0.7]

Total trainable parameters: 209

Training Supervision

Trained with brightness-based proxy labels: for each frame, brightness is mapped to a target tau via the inverse of the adapter's intended behaviour (dark → lower target tau, bright → higher). Loss = MSE(tau_predicted, tau_target). MeMOTR backbone remains fully frozen (0 of 50.4M params trainable).

C1

PositionMLP — Perspective-Weighted Training Loss

⏳ Pending IOTD Calibration

A small MLP that maps each ground-truth box's position (x, y) to a per-box loss weight λ(x, y). Boxes near the camera (typically near the image bottom) receive higher λ because they correspond to closer vehicles where missed detections are more safety-critical. Boxes near the horizon receive lower λ.

Status
C1 requires real perspective calibration from IOTD annotation to map pixel position to metric distance. Implementation is deferred until ≥3 IOTD sequences are annotated and exported. Architecture is designed; training code is ready.

VehicleMOT — Unified Dataset Class

A custom VehicleMOT dataset class (MeMOTR/data/vehiclemot.py) was implemented to handle mixed-format image naming across UA-DETRAC and VisDrone without renaming files. It auto-detects the naming convention per sequence and applies the correct zero-padding. Key design decisions:

  • Sequence-level splits only — frames are never split across train/val boundaries
  • Module-level factory — pickle-safe for Windows spawn multiprocessing
  • Batch size 1 — required for stability with mixed-resolution sequences
  • num_workers=0 — avoids Windows DataLoader deadlock on CUDA ops

Analysis & Interpretation

What C2 Got Right

  • Recall +1.74%, FN −12,497 — C2 correctly identifies that darker frames should have a lower admission threshold, recovering vehicles that the fixed tau=0.5 silently dropped.
  • MT +3.33%, ML −1.01% — More sequences are tracked mostly throughout, fewer go mostly untracked. This is the core practical improvement.
  • AssA −0.10 (essentially zero) — confirms C2 operates only at detection admission and has no effect on MeMOTR's track memory or re-identification. Zero regression.
  • LocA −0.08 (negligible) — bounding box quality unchanged.
  • Clamp verified — tau stayed within [0.3, 0.7] across all 30 probed frames of the hardest sequence. No implementation bug.

The uav0000117 Problem — Root Cause

This single UAV night sequence caused 58,115 of the 69,538 total FP increase (84%). The mean scene brightness was 0.1805, which correctly caused tau to drop to ~0.341 (near tau_min=0.3). However, at this UAV altitude and resolution, MeMOTR's 300 det-queries consistently score above 0.34 regardless of whether they correspond to real vehicles — because the model was never trained at this altitude/scale.

This is a domain shift problem, not a threshold calibration problem. The fix is not to raise tau_min (which would hurt night detection for IOTD) but to provide the adapter with UAV-altitude training examples that teach it to use a higher tau for low-altitude footage despite low brightness.

Expected Phase 6 Proper Outcome
With IOTD night sequences in the training set, the adapter will learn: (a) dark + road = low tau (correct, as intended), and (b) dark + UAV-altitude = higher tau (new signal). This will eliminate the FP explosion.

DETRAC-Only C2 Performance

Excluding the UAV sequence, C2 shows a reasonable trade-off: FP increase of only +11,423 (vs. +69,538 combined), with the FN and MT gains intact. Multiple DETRAC sequences show small HOTA/MOTA improvements with C2 enabled. This validates the mechanism works correctly on the domain it was trained on.
